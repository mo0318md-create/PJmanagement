# PJ管理 ─ プロジェクト管理・進捗可視化システム

プロジェクトを **プロジェクト > タスク > 子タスク** の3階層で管理し、
現在日・終了日・ステータスから「対応中 / 遅延」を判定して可視化する Web アプリ。

実行基盤は **Google Apps Script（ウェブアプリ）＋ スプレッドシート**。

---

## フォルダの構成

| 場所 | 中身 |
|---|---|
| `simple/gas/` | **実装（GAS）**。ここが動くもの |
| `simple/docs/` | 簡易版の要件書・データモデル |
| `simple/mocks/` | 簡易版の画面モック（ブラウザで開ける静的HTML） |
| `docs/` | 完全版の要件書・データモデル（参考。実装していない） |
| `mocks/` | 完全版の画面モック（参考） |

**簡易版**は、完全版から当初計画（ベースライン）・作業の重さと負荷・実績の開始終了日・
マイルストーン・ラベルなどを外したものです。何を落としたかは
[`simple/docs/requirements.md`](simple/docs/requirements.md) の §7 にまとめてあります。

## GAS の動かし方

### 1. スプレッドシートを用意する

新しいスプレッドシートを1つ作ります。
スクリプトをシートに紐づけない（スタンドアロンの）場合は、
Apps Script の「プロジェクトの設定 → スクリプト プロパティ」に
`SPREADSHEET_ID` としてシートのIDを入れてください。

### 2. コードを反映する

```bash
cd simple/gas
npx clasp login      # ブラウザが開くので、使うアカウントで許可する
npx clasp push
```

`.clasp.json` に対象のスクリプトIDが入っています。

### 3. 共通マスタ（社員・所属）をつなぐ

人（担当者・オーナー）は、別システム（稟議システム）と同じ共通マスタから**読むだけ**で使います。

Apps Script の「プロジェクトの設定 → スクリプト プロパティ」に、
共通マスタのスプレッドシートIDを `COMMON_MASTER_SS_ID` として登録してください。
テスト環境では本物ではなくコピーのIDを入れます。

登録したら、エディタで `commonMasterStatus()` を実行すると、届いているか・件数・列名を確認できます（1行も書きません）。

未設定でも動きます。その場合は `users` シートの人を使います。

### 3. 初期化する

Apps Script のエディタで、上から順に実行します。

| 関数 | すること |
|---|---|
| `setup()` | 9つのシートを作り、ヘッダーと初期設定を入れる。実行した人を管理者として登録する |
| `seedSampleData()` | 見本のテンプレートとユーザーを入れる（試したいときだけ） |
| `installDailyTrigger()` | 毎朝7時台に `dailyJob()` を動かすよう仕掛ける |
| `checkSetup()` | 各シートの行数とログイン中の人をログに出す（確認用） |

### 4. 公開する

「デプロイ → 新しいデプロイ → 種類：ウェブアプリ」で公開します。

- **次のユーザーとして実行**：ウェブアプリにアクセスしているユーザー
- **アクセスできるユーザー**：組織内のユーザー（`appsscript.json` の既定）

## 設計の要点

### 2段階で読み込む

GAS の `HtmlService` はページ遷移のたびに `doGet` が走って毎回2〜4秒かかります。
そこで**画面は1ページ**にし、切り替えはブラウザ側で行います。

1. 起動直後 `getBootstrap()` … プロジェクト＋集計キャッシュ＋ユーザー（軽い）
2. 続けて裏で `getItems()` … タスク全件（重い。画面はもう出ている）
3. 保存のたび `saveItem()` など … **変えた1行だけ**を書く

読み込んだあとの判定・集計・検索はすべてブラウザ側で走るので、待ち時間がありません。

### 集計キャッシュ

プロジェクト一覧は `summary_cache` シート（プロジェクト1件につき1行）だけを読んで描きます。
タスク1,000行を待たずに最初の画面が出ます。
タスクを保存するたびに、そのプロジェクトの1行だけ計算し直します。

状態と予定進捗率は「今日」に依存するため、毎朝のトリガーで全件を計算し直します。

### 判定のロジックは2か所にある

`Health.gs`（サーバー）と `health.html`（ブラウザ）に同じ計算があります。
サーバー側は集計キャッシュの更新とお知らせ作りで使います。
**片方を直したら、もう片方も同じに直してください。**

### 状態は終了日だけで決まる

| 順 | 条件 | 状態 |
|---|---|---|
| 1 | ステータス = 完了 | 完了 |
| 2 | **今日 > 終了日（未完了）** | 遅延 |
| 3 | 開始日・終了日が無い | 期間未設定 |
| 4 | 今日 < 開始日 | 開始前 |
| 5 | 上記以外 | 対応中 |

進捗率は判定に使いません。入力が滞っても判定がぶれない代わりに、
終了日が来るまでは遅れかけていても「対応中」のままです。
「順調」と言い切れないため「対応中」と呼びます。

## シート（9つ）

`users` / `templates` / `template_items` / `template_fields` /
`projects` / `items` / `settings` / `notifications` / `summary_cache`

列の定義は [`simple/docs/data-model.md`](simple/docs/data-model.md) と
`simple/gas/Config.gs` の `SHEETS` にあります。**`Config.gs` が唯一の正**です。

- 1行目がヘッダー。コードは列名で引くので、並び順を変えても壊れません
- 主キーは文字列のUUID
- 日付は `yyyy-MM-dd` の文字列（日付型はタイムゾーンでずれるため）

`simple/mocks/rules.html` と要件書 §1 にまとめてあります。
