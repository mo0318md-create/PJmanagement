# 機能要件書 ─ プロジェクト管理・進捗可視化システム

最終更新: 2026-09-28 / フェーズ: 要件定義・モック

---

## 0. システム概要

プロジェクトを **プロジェクト > タスク > 子タスク** の3階層で管理し、
現在日・期間・ステータスから「順調 / 遅延」を自動判定して可視化するWebアプリケーション。

| 項目 | 内容 |
|---|---|
| 想定利用者 | 社内 〜10名（管理者2名 / 担当者8名程度） |
| 想定データ量 | 〜50プロジェクト、1プロジェクトあたり10〜20タスク（合計 〜1,000行） |
| 実行基盤（第1段階） | Google Apps Script + スプレッドシート |
| 実行基盤（将来） | Firebase (Firestore + Hosting) ─ データアクセス層のみ差し替えで移行 |
| 認証 | Googleアカウント（GASのセッションユーザー） |
| 対応デバイス | PC（管理者中心）/ スマートフォン（担当者ビュー） |

## 1. 用語定義

画面・キャンバス・ローカルモック・この要件書で同じ言葉を使う。「使わない言葉」は画面に出さない。

### 1.1 もの

| 用語 | 定義 | 使わない言葉 |
|---|---|---|
| プロジェクト | 第1階層。テンプレートから生成される管理単位 | |
| タスク | プロジェクト配下の作業の**総称**（子タスクを含む）。第2階層だけを指すときは「親タスク」 | 課題、アイテム |
| 子タスク | 第3階層。タスク配下の具体的な作業 | 子課題 |
| 種別 | タスクの種類：作業 / バグ / 要望（テンプレートで定義） | 種別名としての「タスク」 |
| マイルストーン | プロジェクト内の節目。日付は「期日」 | |
| ラベル | 全プロジェクト共通のタグ | |
| テンプレート | プロジェクトの型（タスク構成・固有項目・ステータス列・種別） | |

データモデル上は、タスクと子タスクは同じ `items` テーブル（`level` で区別）に入る。

### 1.2 状態と判定

| 用語 | 定義 | 使わない言葉 |
|---|---|---|
| ステータス | 利用者が選ぶ状態。**名前はプロジェクトごと**（例：レビュー待ち） | |
| 分類 | 各ステータスが持つ4種：未着手 / 進行中 / 保留 / 完了。判定と横断の絞り込みは分類だけを見る | |
| 健全性 | システムが自動で出す状態：**開始前** / 順調 / 注意 / 遅延 / 完了 / 期間未設定 | 未開始（分類の「未着手」と紛らわしいため） |
| 判定モード | 実績進捗率の求め方（自動集計 / 進捗率手入力 / 終了日超過のみ）。プロジェクト設定でだけ変える | 進捗の判定 |
| 予定進捗率 / 実績進捗率 | 期間に対する経過日数の割合 / 実際の進み具合（0〜100%） | |

### 1.3 日付

| 用語 | 定義 | 使わない言葉 |
|---|---|---|
| 開始日・終了日 | いまの予定の期間（項目名） | 締切 |
| 期限 | 終了日の言い換え。**区分名だけ**に使う：今日期限・今週期限・期限順・期限まで | 期限切れ |
| 超過+N日 | 未完了のまま終了日を過ぎた日数 | N日遅れ |
| 実績開始日・実績終了日 | 実際に始めた日・終えた日（§3.8） | |
| 当初計画 | 計画確定（または引き直し）時に保存した予定。画面では「当初計画」「当初比」 | 画面での「ベースライン」 |
| 期日 | マイルストーンの日付。過ぎて未完了のタスクが残ると「期日超過」 | |

### 1.4 人と負荷

| 用語 | 定義 | 使わない言葉 |
|---|---|---|
| 担当者 | タスクを受け持つ人。画面上の人の呼び方はこれに統一 | メンバー |
| ユーザー | ログインアカウント。設定の「ユーザーと稼働」でだけ使う | |
| 未アサイン | 担当者が決まっていないタスク | |
| 作業の重さ | 1件のタスクの人日（§3.7） | 工数（入力項目の「予定工数(h)」は除く） |
| 負荷 | 週ごとの作業の重さの合計（人日） | 作業量 |
| 稼働 | その人がその週に働ける人日（§3.6） | |
| 負荷率 | 負荷 ÷ 稼働 | |
| 稼働超過 | 負荷率が100%を超えること | 負荷過多、オーバー |

### 1.5 画面

| 用語 | 定義 | 使わない言葉 |
|---|---|---|
| ガント | 期間を横棒で並べた図。② 全プロジェクト・⑥ 1プロジェクト・⑭ 担当者別の3つ | タイムライン |
| プロジェクト一覧 | プロジェクト単位の入口（①） | ダッシュボード |
| 担当者一覧 | 担当者単位の入口（⑬） | メンバー一覧 |
| 個人ページ | 1人分の状況（⑮）。自分の分は「マイタスク」（⑯） | |
| お知らせ | 画面内の知らせ（ヘッダーのベル）。メール・チャットへの送信はスコープ外 | 通知 |

### 1.6 画面の役割分担（同じ操作を2か所に置かない）

| 操作・表示 | 行う画面 | ほかの画面では |
|---|---|---|
| 判定モードの変更 | ⑧ プロジェクト設定 | ③ 概要は現在値の表示と⑧への行き先だけ |
| プロジェクト内の画面の移動 | 各画面のタブ（概要・ボード・リスト・ガント・当初計画・設定） | 左ナビにビューのリンクを重ねて置かない |
| 他の担当者の状況を見る | ⑮ 個人ページ（⑬から開く） | ⑯ マイタスクは自分専用（表示する人の切替を置かない） |
| 担当の付け替え | ⑭ 担当者別ガント（ドラッグ／担当メニュー）、⑩ タスク詳細 | |
| 当初計画の確定・引き直し | ⑦ 当初計画 | ⑧ からは⑦へのリンクだけ |
| システム全体の値（しきい値・稼働・祝日など） | ⑰ 設定 | ⑲ 判定ルールは現在値の表示だけ |

## 2. 機能要件一覧

### F-1 プロジェクトテンプレート機能

| ID | 要件 | 優先度 |
|---|---|---|
| F-1-1 | テンプレートを選択してプロジェクトを作成すると、配下のタスク・子タスクが自動生成される | 必須 |
| F-1-2 | テンプレート内の日付は「プロジェクト開始日からの相対日数（開始オフセット・期間日数）」で保持し、作成時に実日付へ展開する | 必須 |
| F-1-3 | テンプレートごとに**カスタム設定項目**を定義できる（項目キー・表示名・型・必須有無・選択肢・表示順） | 必須 |
| F-1-4 | カスタム項目の型は text / number / date / select / checkbox の5種を用意する | 必須 |
| F-1-5 | プロジェクト作成フォームは、選択したテンプレートのカスタム項目を動的に表示する | 必須 |
| F-1-6 | 作成前に「生成されるタスク構成」と「展開後の実日付」をプレビューできる | 必須 |
| F-1-7 | テンプレートのCRUD画面を用意する（タスク構成の追加・削除・並べ替え、カスタム項目の編集） | 必須 |
| F-1-8 | 既存テンプレートを複製して新テンプレートを作成できる | 任意 |
| F-1-10 | テンプレートで**ステータス列**（名前と分類：未着手／進行中／保留／完了）と**タスクの種別**（例：作業／バグ／要望）を定義できる。作成時にプロジェクトへコピーする | 必須 |
| F-1-9 | テンプレートの変更は、既存プロジェクトには**遡及しない**（作成時点でコピーされる） | 必須 |

**設計方針**: 新しいプロジェクトの型が増えてもコード変更が不要になるよう、
カスタム項目はテンプレート側にメタデータとして定義し、プロジェクトにはJSONで値のみを保存する。

### F-2 期間と進捗の自動判定機能

| ID | 要件 | 優先度 |
|---|---|---|
| F-2-1 | プロジェクト・タスク・子タスクのすべてに「開始日」「終了日」を設定できる | 必須 |
| F-2-2 | すべての階層に「ステータス」を設定できる。ステータスの名前はプロジェクトごとに決め、各ステータスは分類（未着手 / 進行中 / 保留 / 完了）を1つ持つ（F-1-10） | 必須 |
| F-2-3 | 現在日・期間・ステータスの分類から健全性を自動判定する（§3参照） | 必須 |
| F-2-4 | 判定方式を **auto / manual / deadline** の3モードから選択できる | 必須 |
| F-2-5 | 判定モードはプロジェクト単位で設定し、未設定時はシステム既定値を継承する | 必須 |
| F-2-6 | 健全性は色バッジ（緑=順調 / 黄=注意 / 赤=遅延 / 青=完了 / 灰=開始前）で視覚化する | 必須 |
| F-2-7 | 進捗バーには「予定進捗ライン」のマーカーを重ねて表示し、予実の差を一目でわかるようにする | 必須 |
| F-2-8 | 未完了のまま終了日を過ぎたタスクには「超過+N日」を表示する（予実差 §3.8 と同じ書き方） | 必須 |
| F-2-9 | 親（プロジェクト・タスク）の実績進捗率は子から積み上げて算出する | 必須 |
| F-2-10 | 子タスクの開始日・終了日が親タスクの期間を外れる場合は警告表示する | 任意 |
| F-2-11 | 色だけに依存せず、アイコン／テキストラベルも併記する（色覚多様性への配慮） | 必須 |
| F-2-12 | 親の実績進捗率は、子の**加重平均**で求める。重みは設定で「期間日数（既定）」か「作業の重さ」から選べる（§3.2.1、§3.7） | 必須 |
| F-2-13 | **当初計画（ベースライン）**を保持し、当初比の後ろ倒し日数と当初日程での健全性を表示する（§3.4）。当初計画は作成時ではなく**計画確定時**に保存する | 必須 |
| F-2-14 | 当初計画の引き直しは**管理者の明示操作**でのみ行う。担当者が日付を直しただけでは当初計画は変わらない | 必須 |
| F-2-18 | プロジェクトは「計画中」で始まり、管理者が「計画を確定」した時点の日付を当初計画の第1版として保存する。計画中は日付を何度直しても当初比を出さない | 必須 |
| F-2-19 | 引き直しは**版**として残す。対象は「プロジェクト全体」または「選んだタスクだけ」（入力ミスの訂正など）。理由は必須。前の版は消さず、比較する版を画面で選べる | 必須 |
| F-2-20 | 確定後に追加したタスクは、追加した時点の日付を当初計画とし、後ろ倒しではなく「確定後に追加」として区別して表示する | 必須 |
| F-2-16 | タスクに**作業の重さ**を持つ。サイズ（S/M/L/XL）または予定工数(h)で入力でき、未入力は期間から自動推定する（§3.7） | 必須 |
| F-2-17 | **実績の開始日・終了日**を記録する。ステータスの分類が初めて「進行中／保留／完了」になった日を実績開始日、「完了」になった日を実績終了日として自動記録し、手で直すこともできる。親は配下から求める（開始＝配下で最も早い実績開始、終了＝自身が完了なら配下で最も遅い実績終了）（§3.8） | 必須 |

### F-0 画面の軸（プロジェクト単位／担当者単位）

画面全体を「プロジェクト単位」と「担当者単位」の2つの軸で構成し、ヘッダーの切替で行き来する。

| ID | 要件 | 優先度 |
|---|---|---|
| F-0-1 | ヘッダーに「プロジェクト単位／担当者単位」の切替を置き、今どちらの軸で見ているかを常に表示する | 必須 |
| F-0-2 | プロジェクト単位＝プロジェクト一覧 → プロジェクト詳細（概要・ボード・リスト・ガント）の順にたどれる | 必須 |
| F-0-3 | 担当者単位＝担当者一覧（「負荷の一覧」と「ガント」をタブで切替） → 個人ページの順にたどれる。自分の個人ページは「マイタスク」から1クリックで開ける | 必須 |
| F-0-4 | サイドナビも2つの軸でグループ分けする（プロジェクト単位／担当者単位／管理） | 必須 |

### F-3 プロジェクト単位のビュー

| ID | 要件 | 優先度 |
|---|---|---|
| F-3-1 | 全プロジェクトを一覧表示し、健全性・実績進捗率・期間・残日数を並べて俯瞰できる | 必須 |
| F-3-2 | 画面上部に「遅延 / 注意 / 順調 / 開始前 / 完了」の件数サマリを表示する | 必須 |
| F-3-3 | 健全性・担当者・テンプレート種別・期間でフィルタできる | 必須 |
| F-3-4 | 遅延度合い順・期限順・名前順でソートできる | 必須 |
| F-3-5 | プロジェクト詳細で、タスク〜子タスクのツリーを展開／折りたたみ表示できる | 必須 |
| F-3-6 | プロジェクト詳細で、各タスクの期間をガントチャートで表示する。日付軸は**月の帯＋週（月曜）の目盛り**とし、表示期間が4か月を超えると月の目盛りに切り替える。今日の位置は縦線と「今日 M/D」ラベルで示す。各行は**予実の2段**（上段＝予定の枠線バー、下段＝実績の塗りバー。進行中は今日まで▶で伸ばす）とし、左に「予定 開始〜終了（日数）」「実績 開始〜終了／進行中／未着手」と予実差（開始+1日・終了+2日・超過+4日・開始遅れ+3日）を出す | 必須 |
| F-3-7 | 階層ごとの消化状況（例: タスク 2/4 完了、子タスク 7/11 完了）を表示する | 必須 |
| F-3-8 | プロジェクトのカスタム項目の値を詳細画面に表示する | 必須 |
| F-3-9 | 詳細画面から「遅延しているタスクだけ表示」に絞り込める | 必須 |
| F-3-10 | プロジェクトを**アーカイブ**（一覧・負荷・横断検索から外す）／解除できる。操作はプロジェクト設定で行い、一覧には「完了も表示」「アーカイブも表示」を別々に置く。データは消さない | 必須 |
| F-3-13 | **プロジェクト設定画面**：名称・説明・オーナー・期間・判定モード・固有項目の値・ステータス列（このプロジェクトだけ）を編集できる。プロジェクト内の各画面のタブ「設定」から開く。**判定モードはこの画面でだけ変更する**（概要は表示と行き先のみ）。編集は管理者とオーナーのみ | 必須 |
| F-3-14 | **マイルストーン**をプロジェクトごとに作成・名前変更・期日変更・削除できる（プロジェクト設定）。タスクにはタスクの編集画面で紐づける。期日を過ぎて未完了のタスクが残ると「期日超過」とし、ガントに◆と縦線で出す | 必須 |

### F-4 担当者単位のビュー

| ID | 要件 | 優先度 |
|---|---|---|
| F-4-1 | ログインユーザーにアサインされたタスク・子タスクを、プロジェクト横断で一覧表示する | 必須 |
| F-4-2 | 期限に応じて **遅延 / 今日期限 / 今週（7日以内）/ 以降 / 完了済み** に区分して表示する | 必須 |
| F-4-3 | 各行に所属プロジェクト名・親タスク名を表示し、どの文脈の作業かわかるようにする | 必須 |
| F-4-4 | 一覧から直接ステータスを変更できる（画面遷移なし） | 必須 |
| F-4-5 | 未完了件数・遅延件数をバッジで表示する | 必須 |
| F-4-6 | マイタスクは**自分専用**とし、表示する人の切替は置かない。他の担当者の状況は個人ページ（F-4-8）で確認する | 必須 |
| F-4-7 | スマートフォン幅（375px）で快適に操作できるレイアウトとする。ナビゲーションは**下部タブバー**（一覧／検索／担当者／マイタスク／設定の5項目、タップ領域48px）に切り替え、ページ全体を横にはみ出させない（横に長い表・ガントはカードの中だけ横スクロール、画面内のタブも横スクロール） | 必須 |
| F-4-8 | **個人ページ**：1人分の「担当タスク（遅延／今日／今週／以降／完了）・週ごとの負荷率・関わっているプロジェクトとその健全性・担当分のガント」を1画面にまとめる。管理者は他の担当者のページも開ける | 必須 |
| F-4-9 | 個人ページの件数・重さ・負荷率は、担当者一覧（F-4-13）と同じ数え方（作業単位）にし、2画面で数字が食い違わないようにする | 必須 |
| F-4-10 | **担当者別ガント**：全員分を「担当者 ＞ プロジェクト ＞ タスク」の順に1本の時間軸へ並べる。担当者の行に週ごとの負荷率を色帯で重ね、行ごとに開閉できる。「プロジェクトでまとめる」を外すと担当者の下にタスクを開始日順に並べる。担当者の絞り込み・完了の表示切替ができる。各行は予実の2段（F-3-6） | 必須 |
| F-4-11 | **担当の付け替え**：担当者別ガントで、タスクの予定バーを別の担当者の行へドラッグすると担当者が変わる。負荷の帯はその場で再計算し、付け替え先が稼働超過になる場合は警告する。「元に戻す」で取り消せる。ドラッグできない環境向けに各行の担当メニューからも同じ操作ができる。付け替えは更新履歴に残し、新旧の担当者にお知らせを出す（F-5-9） | 必須 |
| F-4-12 | 担当者一覧の週ごとの表では、マスに出す数字（負荷率 % ／ 負荷 人日 ／ 件数）を切り替えられる。選んだ数字の意味を表の上に1行で出す | 必須 |
| F-4-13 | **担当者別の負荷**（担当者一覧）：担当者ごとに未完了件数・遅延件数・今日期限・関わるプロジェクト数・作業の重さの合計と、週ごとの負荷（§3.6）を並べ、未アサインのタスクも併記する | 必須 |

### F-5 共通・管理機能

| ID | 要件 | 優先度 |
|---|---|---|
| F-5-1 | ユーザー管理（氏名・メール・ロール admin/member・有効フラグ） | 必須 |
| F-5-3 | システム設定：既定の判定モード、注意/遅延のしきい値を変更できる | 必須 |

## 3. 進捗判定ロジック

### 3.1 予定進捗率（全モード共通）

期間は**両端を含む日数**で数える。

```
総日数   = (終了日 - 開始日) + 1
経過日数 = (今日   - 開始日) + 1
予定進捗率 = clamp(経過日数 / 総日数, 0, 1)
```

### 3.2 実績進捗率（モード別）

| モード | 表示名 | 実績進捗率の求め方 |
|---|---|---|
| `auto` | 自動集計（既定） | 分類=完了なら100%。子を持つなら子の実績進捗率の加重平均（§3.2.1）。子を持たないなら分類から換算（未着手0% / 進行中50% / 保留50% / 完了100%） |
| `manual` | 進捗率手入力 | そのタスクに入力された進捗率を使う。未入力なら auto と同じ計算にフォールバック |
| `deadline` | 終了日超過のみ | 進捗率を使わない。「今日 > 終了日 かつ 未完了」なら遅延、それ以外は順調 |

### 3.2.1 親への積み上げ（期間日数による加重平均）

親（プロジェクト・タスク）の実績進捗率は、**子の期間日数を重みとした加重平均**で求める。

```
親の実績進捗率 = Σ(子の実績進捗率 × 子の期間日数) ÷ Σ(子の期間日数)
子の期間日数   = (終了日 - 開始日) + 1        ※期間未設定の子は 1
```

単純平均にすると、**半日で終わる作業と2週間かかる作業が同じ重み**になり、小さいタスクを先に片付けるだけで進捗が実態より大きく進んで見える。工数（人日）を入力させずに実態へ近づけるため、期間日数を工数の代理値として使う。

| 例（親の下に2タスク） | 単純平均 | 期間日数で加重 |
|---|---|---|
| 1日のタスク=完了 / 9日のタスク=未着手 | 50% | **10%** |
| 1日のタスク=未着手 / 9日のタスク=完了 | 50% | **90%** |
| 5日 / 5日（同じ長さ） | 50% | 50%（同じ） |

重みは設定 `rollup_weight` で「作業の重さ」（§3.7）にも切り替えられる。実装は `health.js` の `rollupRate()` に閉じている。

### 3.3 健全性の判定

上から順に評価し、最初に合致したものを採用する。

| 順 | 条件 | 健全性 | 色 |
|---|---|---|---|
| 1 | 分類 = 完了 | `done` 完了 | 青 |
| 2 | 今日 < 開始日 | `not_started` 開始前 | 灰 |
| 3 | モード = deadline かつ 今日 > 終了日 | `delayed` 遅延 | 赤 |
| 4 | モード = deadline（上記以外） | `on_track` 順調 | 緑 |
| 5 | 今日 > 終了日（未完了） | `delayed` 遅延 | 赤 |
| 6 | 差分 >= -10% | `on_track` 順調 | 緑 |
| 7 | 差分 >= -25% | `at_risk` 注意 | 黄 |
| 8 | 上記以外 | `delayed` 遅延 | 赤 |

```
差分 = 実績進捗率 - 予定進捗率
```

しきい値 -10% / -25% はシステム設定で変更できる（F-5-3）。

### 3.4 当初計画（ベースライン）

予定進捗率は**現在の**開始日・終了日から計算するため、そのままでは**終了日を後ろへずらした瞬間に遅延が消える**。当初計画を別に持ち、日程変更そのものを見えるようにする。

**保存のタイミング（他社SaaSと同じく「確定時に人が保存」）**

| 状態・操作 | いまの予定（`start/end_date`） | 当初計画 |
|---|---|---|
| 作成直後（計画中） | 自由に直せる | **まだ無い**。当初比は出さない |
| 管理者が「計画を確定」 | そのまま | その時点の日付を**第1版**として保存 |
| 確定後に担当者が日付を直す | 更新 | **変えない** → 当初比に出る |
| 管理者が「引き直し」（全体） | そのまま | いまの日付で**新しい版**を作る |
| 管理者が「引き直し」（選んだタスクだけ） | そのまま | 選んだタスクだけいまの日付にした**新しい版**を作る（入力ミスの訂正など） |
| 確定後にタスクを追加 | 入力値 | 追加した時点の日付。「確定後に追加」として表示 |

- 引き直しの理由は必須（種類＋具体的な理由）。履歴に「版・日時・実行者・対象・理由」を残す。
- 前の版は消さない。画面で**比較する版**を選ぶと、当初比・当初日程での健全性・ガントの灰色線をその版で計算し直す（既定は最新版）。
- 参考：Microsoft Project（手動でベースライン保存、最大11版、選んだタスクだけ上書き可）、Wrike・monday.com（スナップショットを複数保存して比較）、Smartsheet（1つを上書き）。作成時に自動で固定する製品は見当たらない。

**画面に出す値**

| 値 | 意味 | 表示例 |
|---|---|---|
| `slipDays` | 現在の終了日 − 当初の終了日。正なら後ろ倒し | 「当初比 +15日」 |
| `baselineHealth` | 当初日程で判定した健全性 | 現在日程では「注意」でも当初比では「遅延」 |
| `slippedCount` | 配下で後ろ倒しされたタスク件数 | 「後ろ倒し 3件」 |

- 当初計画の無いタスク（計画中のプロジェクト、既存データの移行分など）は `slipDays` が空となり、当初比の表示は出さない。通常の判定はこれまでどおり動く。

### 3.5 補足ルール

- **親の健全性は自身の期間で判定する**（子の健全性の最悪値を伝播させない）。
  ただし一覧では「配下の遅延件数」を併記し、親が順調でも中に遅延があることがわかるようにする。
- 保留（on_hold）は進捗率50%換算とし、健全性判定は通常どおり行う。一覧では保留チップを別途表示する。
- 開始日・終了日が未設定のタスクは健全性の判定対象外とし、「期間未設定」と表示する。

### 3.6 担当者別の負荷

担当者ごとの負荷を、作業の重さ（§3.7）から求める（F-4-13）。

- **数える単位＝作業単位**：子タスク、または子を持たないタスク。子を持つタスクは中身と二重になるので数えない。完了（分類 done）と、アーカイブ済みプロジェクトの配下は除く。
- **稼働日**＝月〜金のうち祝日・会社休日でない日（F-5-7）。
- **重さの配り方**：1件の重さを期間の**稼働日**に均等に配る（土日・祝日には配らない）。稼働日が1日も無い期間だけは暦日で配る。
  終了日を過ぎて未完了のものは「今日まで続いている」とみなし、期間を今日まで延ばして配る（放置しても負荷が消えないようにするため）。
- **週ごとの負荷**（人日） ＝ Σ(1件の重さ × その週にかかる稼働日数 ÷ 期間の稼働日数)
- **稼働（その人のその週）** ＝ 週の稼働人日（人ごと。既定 5）×（その週の稼働日のうち本人が休みでない日）÷ 5
- **負荷率** ＝ 週ごとの負荷 ÷ その人のその週の稼働
- **表示の切替**（F-4-12）：

  | 見方 | セルの値 | 緑 | 黄 | 赤 |
  |---|---|---|---|---|
  | 負荷率 | % | 70%未満 | 70〜100% | 100%超 |
  | 負荷（人日） | 人日 | 稼働の7割未満 | 7割〜稼働 | 稼働超過 |
  | 件数 | 同時進行数 | 1〜2件 | しきい値−1 | `overload_threshold`（既定4）以上 |

- **ラベル**（上から優先）：

  | ラベル | 条件 |
  |---|---|
  | 稼働超過 | 表示期間のうち、赤の週が2週以上 |
  | 遅延集中 | 遅延中の作業単位が2件以上 |
  | 余力あり | 表示期間中、どの週も黄に届かない |

- 期間が未設定の作業単位は週ごとの負荷に配れないため、件数と重さの合計にだけ入る。

### 3.7 作業の重さ（人日）

1件の重さは次の順で決まる（F-2-16）。上にあるものが優先。

| 優先 | 入力 | 人日への換算 | 表示 |
|---|---|---|---|
| 1 | 予定工数 `estimate_hours` | 工数 ÷ `hours_per_day`（既定 8） | 濃字 |
| 2 | サイズ `size_key` | `size_days`（既定 S=0.5 / M=2 / L=5 / XL=10） | 濃字 |
| 3 | 未入力 | 期間から推定したサイズの人日 | うす字＋「推定」 |

- **自動推定**：期間日数が 3日以内＝S、7日以内＝M、20日以内＝L、それ以上＝XL。
- **親・プロジェクトの重さ**＝配下の合計。
- **狙い**：入力が無くても数字が出るので初日から使え、実感と違うものだけ直せば精度が上がる。入力は1クリック（サイズ）で済み、時間で管理したいタスクだけ予定工数を入れられる。
- **進捗の重み**（F-2-12）：§3.2.1 の加重平均の重みを、設定 `rollup_weight` で「期間日数（既定）」か「作業の重さ」から選ぶ。既定のままなら従来の判定結果は変わらない。切り替えると、重いタスクが止まっている場合に実績進捗が下がる。

### 3.8 予実（予定と実績）

| 用語 | 意味 |
|---|---|
| 予定 | いまの開始日・終了日（`start_date` / `end_date`） |
| 実績 | 実際に始めた日・終えた日（`actual_start_date` / `actual_end_date`） |
| 当初計画 | 計画確定時（または引き直し時）に保存した予定（ベースライン、§3.4） |

- **記録のしかた**：ステータス変更時に自動で入れる。分類が初めて進行中／保留／完了になった日 → 実績開始日。完了になった日 → 実績終了日。完了から戻したら実績終了日は空に戻す。手で直せる。
- **予実差**（＋が遅れ）：
  - 開始の差 ＝ 実績開始日 − 予定開始日
  - 終了の差 ＝ 実績終了日 − 予定終了日（完了したものだけ）
  - 超過 ＝ 今日 − 予定終了日（未完了で予定終了日を過ぎたもの）
  - 開始遅れ ＝ 今日 − 予定開始日（未着手で予定開始日を過ぎたもの）
- **表示**：ガントの各行を2段にし、上段に予定（枠線）、下段に実績（塗り）を描く。進行中の実績は今日まで伸ばし、右端を▶にする。
- **健全性（順調／遅延）の判定は変えない**。予実差は「どこでずれたか」を読むための補助情報とする。
