プロジェクト管理システム ─ 画面モック

要件定義フェーズの確認用モックです。ダミーデータで実際に動きます（サーバー不要）。
日付は開いた日を「今日」として自動生成されます。いつ開いても 「遅延1件・注意1件・順調2件・開始前1件・完了1件」の状態が再現されるので、色や判定の見え方を確認できます。
番号はキャンバス（画面設計）と共通です。⑳〜㉓（タブレット・スマホ版）はキャンバスだけにあり、ローカルでは各画面が幅に合わせて並び替わります。

プロジェクト単位

①
プロジェクト一覧
健全性・進捗・当初比の一覧。件数サマリ、絞り込み、アーカイブも表示。
②
全プロジェクトのガント
全プロジェクトを1本の時間軸に。予実2段、行を開くとタスクまで。
③
プロジェクト概要
概要・タスクツリー・ガント・当初計画をまとめたプロジェクト詳細。
④
ボード
ステータス列のカンバン。ドラッグでステータス変更。
⑤
リスト
表で一覧。ステータス／担当者／マイルストーン／ラベルでまとめる。
⑥
ガント
1プロジェクト内のガント。予実2段・マイルストーン◆・今日線。
⑦
当初計画
計画確定、比較する版、引き直し（全体／選んだタスク）、履歴。
⑧
プロジェクト設定
基本情報・固有項目・ステータス列・マイルストーン・アーカイブ。
⑨
プロジェクト作成
テンプレートを選ぶとタスク構成と日付が展開される。

タスク・テンプレート

⑩
タスクの編集（タスク詳細）

タスク構成・ステータス列・種別・固有項目。（一覧は template-list.html）

⑬
担当者一覧・負荷

⑯
マイタスク

共通・管理

お知らせ

ダミーデータの内容

プロジェクト判定モード期間健全性ねらい

判定ロジックの要約

期間は両端を含む日数で数えます。

予定進捗率 = clamp((今日 - 開始日 + 1) / (終了日 - 開始日 + 1), 0, 1)
差分       = 実績進捗率 - 予定進捗率

実績進捗率の求め方（3モードから選択）

モード求め方
自動集計
auto（既定）
 完了なら100%。子を持つなら子の平均。子を持たないならステータス換算（未着手0% / 進行中・保留50% / 完了100%）。
進捗率手入力
manual
 入力された進捗率を使う。未入力のタスクは自動集計にフォールバック。
終了日超過のみ
deadline
 進捗率を使わず、終了日を過ぎて未完了のものだけを遅延と判定。

健全性の判定（上から順に評価）

条件結果
ステータス = 完了✓完了
今日 < 開始日・開始前
今日 > 終了日（未完了）!遅延
差分 ≧ -10pt●順調
差分 ≧ -25pt▲注意
上記以外!遅延

しきい値は設定画面で変更できます。親（プロジェクト・タスク）の健全性は自身の期間で判定し、 子の遅延は伝播させず「配下の遅延件数」として別に表示します。

モックの構成

mocks/
├── index.html            この画面
├── assets/
│   ├── mock.css          共通スタイル（健全性の配色トークン）
│   ├── health.js         判定ロジック ★本実装でもそのまま流用する
│   ├── mock-data.js      ダミーデータ
│   └── mock-ui.js        ヘッダー／ナビ／バッジ／進捗バー
└── *.html                各画面

ビルド不要のバニラJSです。GASへ移す際は HtmlService の include() で css / js を結合し、データ取得部分だけ google.script.run に差し替えます。
