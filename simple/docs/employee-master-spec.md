## 2. シート構成（4層）

```
第1層 同期タブ   employees / departments / positions      ← API の生データ。触らない
第2層 手動補完   補完_社員所属 / 補完_所属名               ← 人が入力。同期で消えない
第3層 マスタ     所属マスタ / 役職マスタ / 社員マスタ       ← 正規化。コードと固有属性のみ
第4層 ビュー     社員一覧                                  ← 第3層を結合した非正規化の表
```

```
✅ 参照してよい（安定・契約対象）
   社員一覧（推奨）/ 所属マスタ / 役職マスタ / 社員マスタ

⚠️ 参照しないでください（内部構造・予告なく変わる）
   employees / departments / positions / 補完_* / 同期ログ
```

**基本は `社員一覧` だけを読めば足ります。** 組織ツリーが必要なときだけ `所属マスタ` を併用してください。

### 見出しの色と (xronos) の意味

| 色 | 意味 |
|---|---|
| 🟦 青 | XronosLink から無加工で取得した値。見出しに `(xronos)` が付く |
| 🟩 緑 | 本システムが整形・導出・集計した値 |
| 🟨 黄 | 人が入力する値（補完シート） |

## 3. スキーマ

### 社員一覧（ビュー・14列）— 通常はここを読む

主キー: `社員コード(xronos)`

| # | 列名 | 型 | NULL | 説明 |
|---|---|---|---|---|
| A | 社員コード(xronos) | 文字列 | 不可 | **PK** |
| B | 氏名 | 文字列 | 不可 | 「姓 名」。`*` と数字を除去済み（§5） |
| C | 氏名カナ | 文字列 | 不可 | 半角カタカナ。同上 |
| D | 所属コード(xronos) | 文字列 | **可** | **FK → 所属マスタ**。空の場合あり（§6） |
| E | フルパス | 文字列 | 可 | `製造部 空調第一生産課 1係`（**半角スペース区切り**） |
| F | 部門 | 文字列 | 可 | 第1階層の名称 |
| G | 課 | 文字列 | 可 | 第2階層の名称。無ければ空 |
| H | 係 | 文字列 | 可 | 第3階層の名称。無ければ空 |
| I | 役職コード(xronos) | 文字列 | 不可 | **FK → 役職マスタ** |
| J | 役職名(xronos) | 文字列 | 不可 | |
| K | 入社年月日(xronos) | 文字列 | 可 | `yyyy-mm-dd`。**文字列であって日付型ではない** |
| L | 退職年月日(xronos) | 文字列 | 可 | `yyyy-mm-dd`。**空 = 在籍中** |
| M | 在籍区分 | 文字列 | 不可 | `在籍` / `退職` |
| N | 勤続年数 | 数値 | 可 | ⚠️ `TODAY()` 依存。§7.2 参照 |

> `所属名` 列はありません。最深階層の名称は `部門`/`課`/`係` のいずれかと必ず同じ値になるため冗長でした。
> 単独の所属名が必要なら `所属マスタ.名称` を `所属コード` で引いてください。

### 所属マスタ（10列）

主キー: `所属コード(xronos)`

| # | 列名 | 型 | NULL | 説明 |
|---|---|---|---|---|
| A | 所属コード(xronos) | 文字列 | 不可 | **PK**。`1-2-3` 形式（最大9階層） |
| B | 階層 | 数値 | 不可 | 1〜3（`-` の数 + 1） |
| C | 親コード | 文字列 | 可 | **自己参照FK**。最上位は空。隣接リストとして木を組める |
| D | 名称 | 文字列 | 可 | `1係`。正規化済み。**他システムが使うのはこちら** |
| E | 名称(xronos) | 文字列 | 可 | `1係(第一生産課）_空調`。XronosLink の生の値（§5） |
| F | フルパス | 文字列 | 可 | `製造部 空調第一生産課 1係` |
| G | 在籍者数 | 数値 | 不可 | この所属に**直接**属する在籍者 |
| H | 配下在籍者数 | 数値 | 不可 | 自分＋子孫の在籍者。ツリーで空の枝を畳むのに使う |
| I | **状態** | 文字列 | 不可 | `有効`（配下に在籍者あり）/ `未使用`（旧組織） |
| J | 出典 | 文字列 | 不可 | `XronosLink` / `手動補完` / `未入力` / `未登録` |

### 役職マスタ（5列）

主キー: `役職コード(xronos)`

| # | 列名 | 型 | 説明 |
|---|---|---|---|
| A | 役職コード(xronos) | 文字列 | **PK**。`0`〜`18` だが**文字列として扱うこと** |
| B | 役職名(xronos) | 文字列 | `部長` `課長` `主任` `社員` `パート` など |
| C | 在籍者数 | 数値 | 集計値 |
| D | 状態 | 文字列 | `有効` / `未使用` |
| E | 出典 | 文字列 | 常に `XronosLink` |

### 社員マスタ（正規化テーブル・10列）

名称を一切持ちません。`社員一覧` で足りるなら読む必要はありません。

```
社員コード(xronos), 氏名, 氏名カナ, 所属コード(xronos), 役職コード(xronos),
入社年月日(xronos), 退職年月日(xronos), 在籍区分, 勤続年数, 所属の出典
```

`所属の出典` は `XronosLink` / `手動補完` / `未設定`。

## 4. 参照側が必ず守ること

### 4.1 突き合わせは必ずコードで行う

`所属マスタ.名称` は**同じ親の下でのみ一意**です。`1係` は `1-1-1` `1-2-1` `5-1-1` `6-1-1` に存在します。

### 4.2 コードは文字列として扱う

`役職コード` の `0`、`所属コード` の `0-1` を数値や日付として解釈しないでください。
特に **`23-1` のような所属コードは日付にパースされがち**です。
Apps Script では `getValues()` ではなく **`getDisplayValues()`** を使ってください。

### 4.3 日付は ISO 8601 の文字列

`yyyy-mm-dd`。辞書順の比較がそのまま日付順の比較になります。

### 4.4 在籍判定は `在籍区分` を使う

退職者も同じシートに残っています（114名中53名が退職済み）。
承認者候補などは **`在籍区分 = "在籍"` で必ず絞ってください。**

### 4.5 所属・役職は `状態 = "有効"` で絞る

使われなくなった旧組織・旧役職が残っています（XronosLink 側で削除されないため）。

| マスタ | 有効 | 未使用 |
|---|---|---|
| 所属マスタ（35件） | 17件 | **18件** |
| 役職マスタ（19件） | 12件 | **7件** |

- **選択肢を作るとき** → `状態 = "有効"` で絞る
- **過去の申請を表示するとき** → 絞らない（退職者の所属を引けなくなる）

### 4.6 列は増えるが、既存列の順序と意味は変えない

**列名でインデックスを引いてください。**

```javascript
const [header, ...rows] = sheet.getDataRange().getDisplayValues();
const idx = Object.fromEntries(header.map((h, i) => [h, i]));
const code = row[idx['社員コード(xronos)']];
```

## 5. XronosLink 由来の癖（クリーニング済み）

参照側で再実装は不要です。マスタ側で処理済みです。

| 癖 | 実データ | マスタでの扱い |
|---|---|---|
| 氏名に `5*` `8` `*` の接尾辞 | 114名中37名（`*` 56回・数字72回） | 除去済み。除去後も**氏名の重複は0件** |
| 全角スペース混在 | 1件 | 半角1個に統一 |
| 所属名に親の文脈が埋め込まれている | `1係(第一生産課）_空調` | `名称` に `1係`、`名称(xronos)` に原文 |
| 括弧の全角・半角混在 | `(…）` と `（…）` | 両方に対応 |

## 7. マスタとして「弱い」点（設計上の割り切り）

### 7.1 履歴がない（重要）

現時点のスナップショットです。毎朝の同期で過去の状態は失われます。

> **稟議システムのように「申請時点の所属・役職」を残す必要がある場合、
> 申請レコード側に所属コード・役職コードを複写して保存してください。**

### 7.2 `勤続年数` は揮発性

`TODAY()` で計算しているため読むたびに変わります。キャッシュや突き合わせに使わないでください。

### 7.3 非正規化されたビューである

`社員一覧` の `フルパス` `部門` `課` `係` は `所属コード` から導出可能な冗長列です。
**正となるのは常にコードです。**

### 7.4 削除の検知ができない

洗い替え方式のため、XronosLink から社員が削除されるとマスタからも消えます。
参照側に外部キーが残ると宙に浮きます。§7.1 と同じ対策が必要です。

### 7.5 社員コードと IDコード

XronosLink には2つありますが実データでは**1名だけ不一致**（`社員コード=285` / `IDコード=332`）。
マスタには `社員コード` のみを載せています。

## 9. 読み取り方法

### 9.1 同じ Workspace 内の Apps Script から（推奨）

```javascript
const MASTER_SS_ID = '12MpVms4VPRQ_6nOqpnWsNK44R5kraK8RibbWTcG5fe0';

/** 在籍中の社員を返す。列名で引くので列が増えても壊れない。 */
function fetchActiveEmployees() {
  const sheet = SpreadsheetApp.openById(MASTER_SS_ID).getSheetByName('社員一覧');
  const [header, ...rows] = sheet.getDataRange().getDisplayValues();
  const idx = Object.fromEntries(header.map((h, i) => [h, i]));

  return rows
    .filter(r => r[idx['社員コード(xronos)']] !== '' && r[idx['在籍区分']] === '在籍')
    .map(r => ({
      code:     r[idx['社員コード(xronos)']],
      name:     r[idx['氏名']],
      kana:     r[idx['氏名カナ']],
      deptCode: r[idx['所属コード(xronos)']],
      deptPath: r[idx['フルパス']],
      division: r[idx['部門']],
      posCode:  r[idx['役職コード(xronos)']],
      posName:  r[idx['役職名(xronos)']],
    }));
}

/** 選択肢に出してよい所属だけを返す。 */
function fetchActiveDepartments() {
  const sheet = SpreadsheetApp.openById(MASTER_SS_ID).getSheetByName('所属マスタ');
  const [header, ...rows] = sheet.getDataRange().getDisplayValues();
  const idx = Object.fromEntries(header.map((h, i) => [h, i]));

  return rows
    .filter(r => r[idx['所属コード(xronos)']] !== '' && r[idx['状態']] === '有効')
    .map(r => ({
      code:      r[idx['所属コード(xronos)']],
      parent:    r[idx['親コード']],      // 空 = 最上位。木を組むのに使う
      level:     Number(r[idx['階層']]),
      name:      r[idx['名称']],
      path:      r[idx['フルパス']],
      headcount: Number(r[idx['在籍者数']]),
    }));
}
```

必要な OAuth スコープ:

```
https://www.googleapis.com/auth/spreadsheets.readonly
```

※ マスタ側が使う `spreadsheets.currentonly` では他のスプレッドシートを開けません。

### 9.2 パフォーマンス

- `getDataRange().getDisplayValues()` は1回で全件取れます。行ごとに読まないでください
- 数式ビューなので開くたびに再計算が走ります。頻繁に読むなら `CacheService` に5〜30分キャッシュを推奨

### 9.3 権限

参照側スクリプトの実行アカウントに、**共有ドライブの「閲覧者」以上**が必要です。

> ⚠️ 「投稿者」以上を与えると Apps Script エディタから
> **XronosLink のアクセストークンを読み出せてしまいます**。参照専用なら**必ず「閲覧者」**に。

### 9.4 AppSheet から参照する場合

- **`Updates: Read-Only` にしてください。** 数式列は書き込めません
- **行の追加・削除を無効にしてください。** 追加すると `ARRAYFORMULA` が壊れます
- **キー列は `社員コード(xronos)`**。行番号をキーにすると並び替えでずれます
- 洗い替え方式のため、同期のたびに全行が「変更あり」と判定されます

### 9.5 数式が壊れるリスク

各シートの**2行目にだけ数式**があり、3行目以降はその展開結果です。
**2行目を誰かが編集すると全体が壊れます。** シート保護の設定を推奨します（未実施）。

## 10. 変更管理

| | |
|---|---|
| 列の追加 | 予告なく行う場合があります |
| 列の削除・改名・意味の変更 | 事前に連絡します |
| 同期の停止 | アクセストークンには有効期限があります。切れると同期が止まり、古い値のまま残ります |
| 障害の検知 | `同期ログ` の最終行が `成功` かつ当日日付かで判定できます |

```javascript
function isMasterFresh() {
  const sheet = SpreadsheetApp.openById(MASTER_SS_ID).getSheetByName('同期ログ');
  if (!sheet || sheet.getLastRow() < 2) return false;   // シートが無い／実行履歴が無い
  const last = sheet.getRange(sheet.getLastRow(), 1, 1, 2).getDisplayValues()[0];
  const today = Utilities.formatDate(new Date(), 'Asia/Tokyo', 'yyyy-MM-dd');
  return last[1] === '成功' && last[0].startsWith(today);
}
```
