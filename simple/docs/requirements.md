# 機能要件書（簡易版）─ プロジェクト管理・進捗可視化システム

最終更新: 2026-09-28 / フェーズ: 要件定義・モック / 版: **簡易版 v1**

完全版の要件書は `../../docs/requirements.md`。要件IDは完全版と揃えてあるので、
**歯抜けになっている番号は簡易版で削ったもの**（§7 に一覧）。

## 0. システム概要

プロジェクトを **プロジェクト > タスク > 子タスク** の3階層で管理し、
現在日・期間・ステータス・進捗率から「順調 / 遅延」を判定して可視化する **Google Apps Script の Web アプリ**。

| 項目 | 内容 |
|---|---|
| 想定利用者 | 社内 〜10名（管理者2名 / 担当者8名程度） |
| 想定データ量 | 〜50プロジェクト、1プロジェクトあたり10〜20タスク（合計 〜1,000行） |
| 実行基盤 | **Google Apps Script（Web アプリ）＋ スプレッドシート** |
| 認証 | Googleアカウント（`Session.getActiveUser()`） |
| 対応デバイス | PC（管理者中心）/ スマートフォン（担当者中心）。同じ画面がレスポンシブで変形する |
| 画面構成 | **1ページの Web アプリ**。画面の切替はブラウザ側で行い、サーバーへは行かない（§5） |

## 1. 用語定義

画面・モック・この要件書で同じ言葉を使う。「使わない言葉」は画面に出さない。

| 用語 | 定義 | 使わない言葉 |
|---|---|---|
| プロジェクト | 第1階層。テンプレートから生成される管理単位 | |
| タスク | プロジェクト配下の作業の**総称**（子タスクを含む）。第2階層だけを指すときは「親タスク」 | 課題、アイテム |
| 子タスク | 第3階層。タスク配下の具体的な作業 | |
| 種別 | タスクの種類：作業 / バグ / 要望（**固定の3種**） | 種別名としての「タスク」 |
| ステータス | 担当者が手で選ぶ区分：未着手 / 進行中 / 保留 / 完了 の**4つ固定**（完全版のようなプロジェクトごとの名前は持たない） | 分類 |
| 状態 | システムが自動で出す区分：**開始前 / 対応中 / 遅延 / 完了 / 期間未設定** の5つ。終了日とステータスだけで決まる（§3.3）。人は直接変えられない | 健全性、未開始、順調、注意 |
| 予定進捗率 | 期間に対する経過日数の割合（0〜100%） | |
| 実績進捗率 | 進み具合（0〜100%）。**末端は手入力、親は子の平均**（§3.2） | |
| 開始日・終了日 | 予定の期間（項目名） | 締切 |
| 期限 | 終了日の言い換え。**区分名だけ**に使う：今日期限・今週期限・期限順・期限まで。期限の日付は **yyyy/mm/dd**（例 2026/10/31）で表示し、「あと N 日」「今日期限」「超過+N日」を出す所には**全画面で日付を添える**（お知らせも同じ）。最終更新・登録の日時も **yyyy/mm/dd HH:MM**、期間も **yyyy/mm/dd〜yyyy/mm/dd** にそろえる（曜日は付けない。ガントの目盛りと「今日」の札だけは短い M/D）。長くなった行は切らずに折り返し、日付と人の名前は途中で割らない | 期限切れ |
| 超過+N日 | 未完了のまま終了日を過ぎた日数 | N日遅れ |
| 担当者 | タスクを受け持つ人 | メンバー |
| ユーザー | ログインアカウント。設定画面でだけ使う | |
| 未アサイン | 担当者が決まっていないタスク | |
| ガント | 期間を横棒で並べた図。**全プロジェクト**・**1プロジェクト内**・**担当者別**・**個人ページ**の4か所 | タイムライン |

### 1.1 画面の役割分担（同じ操作を2か所に置かない）

| 操作・表示 | 行う画面 | ほかの画面では |
|---|---|---|
| プロジェクトの内容の変更 | ⑧ プロジェクトの編集 | ③ 概要は表示と行き先だけ |
| プロジェクト内の移動 | 各画面のタブ（概要・ボード・リスト・ガント・設定） | 左ナビにビューのリンクを重ねて置かない |
| プロジェクトをまたぐ検索 | ⑩ 横断検索 | 各一覧の絞り込みはその画面の中だけ |
| 他の担当者の状況を見る | ⑬ 個人ページ（⑪から開く） | ⑭ マイタスクは自分専用 |
| 担当の付け替え | ⑦ タスクの編集 | |
| システム全体の値 | ⑮ 設定 | ⑱ 判定ルールは現在値の表示だけ |

## 2. 機能要件一覧

### F-1 プロジェクトテンプレート機能

| ID | 要件 | 優先度 |
|---|---|---|
| F-1-1 | テンプレートを選択してプロジェクトを作成すると、配下のタスク・子タスクが自動生成される。作成画面では**有効なテンプレートをすべて**1列のリスト（1行＝名前・説明・使用回数「使用 n」）で出し、「使わない」を先頭、続けてよく使われている順（同数は名前順）に並べる。7件以上あるときは名前・説明・キーの頭で絞り込む欄を付け、リストは高さを抑えた枠の中でスクロールさせる（下の入力欄まで遠くならないように）。数が多くても開くのが遅くならないよう、はじめは50件だけ並べ、「さらに 50 件を表示（残り n 件）」で続きを出す。名前で探すときは全件から探す。選んだテンプレートは見出しの横に「選択中：〇〇」と出す | 必須 |
| F-1-2 | テンプレート内の日付は「プロジェクト開始日からの相対日数（開始オフセット・期間日数）」で保持し、作成時に実日付へ展開する | 必須 |
| F-1-3 | テンプレートごとに**カスタム設定項目**を定義できる（項目キー・表示名・型・必須有無・選択肢・表示順）。**テンプレートは入力の短縮**であって、項目を持てるかどうかを決めるものではない（F-1-13） | 必須 |
| F-1-4 | カスタム項目の型は text / number / date / select / checkbox の5種を用意する | 必須 |
| F-1-5 | プロジェクト作成フォームは、選択したテンプレートのカスタム項目を動的に表示する | 必須 |
| F-1-6 | 作成前に「生成されるタスク構成」と「展開後の実日付」をプレビューできる | 必須 |
| F-1-7 | テンプレートのCRUD画面を用意する（タスク構成の追加・削除・並べ替え、カスタム項目の編集） | 必須 |
| F-1-9 | テンプレートの変更は、既存プロジェクトには**遡及しない**（作成時点でコピーされる） | 必須 |
| F-1-13 | **設定項目はその場でも足せる。** テンプレートを使わないプロジェクトでも、使っているプロジェクトでも、1行＝「項目名・型・値」で項目を足せる。型（文字／数値／日付／選択肢／はい・いいえ）を選ぶと値の入力欄がその型に変わる（日付なら日付の選択、選択肢なら選択肢の入力欄が出る）。テンプレート由来の行は名前・型・必須が決まっていて値だけ入れる。項目の定義は作成時にテンプレートからコピーして `projects.field_defs` に持ち（F-1-9：テンプレートを後で変えても遡及しない）、値は `projects.custom_fields` に入る | 必須 |
| F-1-11 | テンプレートを使わずに空のプロジェクトを作ることもできる。**この場合は並べるタスクが無いので、終了日を入力してもらう**（テンプレートを使うときは自動で決まるため入力させない） | 必須 |
| F-1-12 | プロジェクトの終了日は、テンプレートを使うとき**いちばん後ろのタスクから自動で決まる**（F-1-2）。作成画面では読み取り専用で見せ、開始日を変えると連動して変わる。作成後はプロジェクト設定で直せる | 必須 |

**設計方針**: 新しいプロジェクトの型が増えてもコード変更が不要になるよう、
カスタム項目はテンプレート側にメタデータとして定義し、プロジェクトにはJSONで値のみを保存する。

### F-2 期間と進捗の判定機能

| ID | 要件 | 優先度 |
|---|---|---|
| F-2-1 | プロジェクト・タスク・子タスクのすべてに「開始日」「終了日」を設定できる | 必須 |
| F-2-2 | すべての階層に「ステータス」（未着手 / 進行中 / 保留 / 完了）を設定できる。**4つ固定**とし、プロジェクトごとの名前変更は行わない | 必須 |
| F-2-3 | 現在日・終了日・ステータスから状態を判定する（§3.3）。**進捗率は判定に使わない** | 必須 |
| F-2-6 | 状態は色バッジ（緑=対応中 / 赤=遅延 / 青=完了 / 灰=開始前・期間未設定）で視覚化する | 必須 |
| F-2-7 | 進捗バーには「予定進捗ライン」のマーカーを重ねて表示し、予定と実績の差を一目でわかるようにする。数字は「進捗 X% ／ 予定 Y%」と並べるだけにし、差を「〜pt 遅れ」「予定どおり」のように**言い切らない**（遅れの判定は終了日だけ：F-2-22）。縦線と予定％は F-5-16 で出さない設定にできる | 必須 |
| F-2-8 | 未完了のまま終了日を過ぎたタスクには「超過+N日」を表示する | 必須 |
| F-2-11 | 色だけに依存せず、アイコン／テキストラベルも併記する（色覚多様性への配慮） | 必須 |
| F-2-21 | **進捗率は手入力**とする。子タスクを持たないタスクに 0〜100% を入れ、子を持つタスクとプロジェクトは配下の平均を自動表示する（§3.2） | 必須 |
| F-2-25 | **親子・プロジェクトの完了の連動（Backlog と同じく、確認してから）**。上に連動するのは配下が全件完了のときだけ：①完了していない子タスクがある親タスクを完了にするとき、「すべて完了にする」（子もまとめて完了・進捗100%）／「親タスクのみ完了にする」／やめる、を選ぶ。②最後に残った子タスクを完了にするとき、「親タスクも完了にする」／「子タスクのみ完了にする」／やめる、を選ぶ。③タスクを完了にしてプロジェクトのタスク（子タスクを含む）が**全件完了**になるとき、「プロジェクトも完了にする」／「タスクのみ完了にする」／やめる、を選ぶ（親子の確認のあとに続けて聞く。子のみ・親のみを選んで残りがあるときは聞かない）。④完了していないタスクがあるプロジェクトをプロジェクトの編集で完了にするとき、「すべて完了にする」（全タスク・子タスクを完了）／「プロジェクトのみ完了にする」／やめる、を選ぶ。どれも黙って自動では変えない。タスクの編集・ボード（ドラッグ／スマホの「移動」）・マイタスクのどこから完了にしても同じ確認を出す。子も親も1回の保存でまとめて書き、完了の知らせに何件を完了にしたかを書く。プロジェクトの完了は、③④の確認を経たときだけ連動する。**確認は1回にまとめる**：「どこまで完了にしますか？」に、当てはまる範囲だけを広い順に並べて選ぶ（このタスクだけ／子タスク n 件も／親タスク「〇〇」も／プロジェクト「〇〇」まで。プロジェクトの編集では プロジェクトだけ／残りのタスク n 件も）。最初は1段広い範囲を選んでおく。PC・タブレットは画面中央の小さなダイアログ、スマートフォンは下から出す。タスクの編集では下の帯に同じ選択肢を出す | 必須 |
| F-2-22 | 状態の「遅延」は、**終了日を過ぎて未完了**のときだけとする。進捗率と予定進捗率の差では判定しない（＝「注意」を持たない）。進捗率の入力が滞っても判定がぶれない代わりに、終了日が来るまでは遅れかけていても「対応中」になる | 必須 |

### F-3 プロジェクト単位のビュー

| ID | 要件 | 優先度 |
|---|---|---|
| F-3-1 | 全プロジェクトを一覧表示し、状態・実績進捗率・期間・残日数を並べて俯瞰できる | 必須 |
| F-3-2 | 画面上部に「遅延 / 対応中 / 開始前 / 完了」の件数サマリを表示する。これは**プロジェクトの件数**であることを見出し（「プロジェクトの状態」）と単位で示し、押すとその状態で絞り込む。**遅延しているタスクの件数は別の段**に出し（「遅延しているタスク n 件（m プロジェクト）」）、押すと遅延タスクを持つプロジェクトだけに絞り込む（プロジェクトの状態はプロジェクト自身の終了日で判定するため、両者の数は一致しないことがある） | 必須 |
| F-3-3 | 状態・担当者・テンプレート種別・期間でフィルタできる | 必須 |
| F-3-4 | 遅延度合い順・期限順・名前順でソートできる | 必須 |
| F-3-5 | プロジェクト詳細で、タスク〜子タスクのツリーを展開／折りたたみ表示できる。**子タスクは既定で閉じる**（「すべて開く」でまとめて開ける。「遅延だけ表示」のときは遅れた子が見えるよう開き、子タスクを追加したときはその親を開く）。子タスクは薄い地と左の線で親につなぎ、親の行には「子タスク n件（開閉・配下の遅延数）」と「子タスクを追加」のボタンを出す（リンク文字ではなくボタン。タッチ端末では押す場所を約38px以上）。タスクの編集画面にも、親なら子タスクの一覧と「子タスクを追加」、子なら親タスクへのリンクを出し、親子を行き来できる | 必須 |
| F-3-6 | プロジェクト詳細で、各タスクの期間をガントチャートで表示する。日付軸は2段とし、目盛りの単位を**日／週／月／四半期／全体**で切り替える（全部のガントで共通。PC・タブレット・スマートフォンで同じ）。上の段は日・週なら「2026年9月」、月・四半期なら「2026年」。下の段は日「28 月」（土日は網掛け、今日は赤字）、週「9/21」（週の初日＝月曜）、月「10月」、四半期「10〜12月」。PC・タブレットは単位ごとに1日あたりの幅を変え（拡大・縮小）、はみ出した分は横に流す。「全体」は全期間を画面の幅に収め、目盛りの単位は1日あたりの幅から自動で選ぶ。単位を変えると今日が見える位置から表示し、「今日へ」で今日の位置へ戻れる。スマートフォンは1画面ずつめくる（日＝1週間、週＝4週間、月＝3か月、四半期＝1年）。今日の位置は縦線で示し、PC・タブレットは「今日 M/D」ラベルも出す。各行は**1本のバー**とし、バーの中を進捗率ぶんだけ濃く塗って右端に % を出す。色は状態。左の欄には「タスク名・開始〜終了（日数）・担当者」を出し、遅れているものには「超過+N日」を添える。**左の欄は固定幅で常に見え、時間軸のほうを横スクロールする**（幅が足りないときに名前や日付が切れないようにするため） | 必須 |
| F-3-7 | 階層ごとの消化状況（例: タスク 2/4 完了、子タスク 7/11 完了）を表示する | 必須 |
| F-3-8 | プロジェクトのカスタム項目の値を詳細画面に表示する。表示名は、テンプレート由来なら定義の表示名、その場で足した項目は項目名をそのまま使う | 必須 |
| F-3-9 | 詳細画面から「遅延しているタスクだけ表示」に絞り込める | 必須 |
| F-3-13 | **プロジェクトの編集画面**：名称・説明・オーナー・期間・固有項目の値を編集できる。プロジェクトの頭の「編集」ボタン（鉛筆のアイコン）から開く。編集は管理者とオーナーのみ | 必須 |
| F-3-15 | **ボード**：ステータス4列にタスクをカードで並べ、**ドラッグでステータスを変更**できる（PC・タブレット。マウスは押して動かす、タッチは長押ししてから動かす）。スマートフォンは列を1つずつ表示し（上の4つのボタンで列を切り替え）、各カードの「移動」から行き先の列を選ぶ（画面の外の列まで指で運ばなくてよいように）。カードには担当者・終了日・状態を出す | 必須 |

| F-3-16 | **リスト**：タスクを表形式で並べ、まとめ方（ステータス／担当者／種別）を切り替えられる。行から直接ステータスと進捗率を変更できる | 必須 |

## 3. 進捗判定ロジック

### 3.1 予定進捗率

期間は**両端を含む日数**で数える。

```
総日数   = (終了日 - 開始日) + 1
経過日数 = (今日   - 開始日) + 1
予定進捗率 = clamp(経過日数 / 総日数, 0, 1)
```

### 3.2 実績進捗率（手入力・判定には使わない）

この％は**状態の判定には使わない**（§3.3）。「どこまで進んだか」を人が見るための数字。

| 対象 | 求め方 |
|---|---|
| 子タスクを持たないタスク | 担当者が入れた **進捗率（0〜100%）** をそのまま使う。未入力は 0% |
| 子タスクを持つタスク | **子の実績進捗率の単純平均**（自動。手入力できない） |
| プロジェクト | **配下のタスク（第2階層）の実績進捗率の単純平均**（自動） |

- ステータスを「完了」にしたら、進捗率は自動で 100% にする。
- 完了から戻したときは、100% のまま残す（担当者が直す）。

> 完全版では期間日数や作業の重さで重みを付けた加重平均だったが、
> 簡易版は**単純平均**とする。重みの設定・作業の重さの入力がどちらも無くなるため。
> 大小さまざまなタスクが混ざる親では実態とずれることがある点は、割り切りとして受け入れる。

### 3.3 状態の判定

上から順に評価し、最初に合致したものを採用する。**進捗率は使わない**。

| 順 | 条件 | 状態 | 色 |
|---|---|---|---|
| 1 | ステータス = 完了 | `done` 完了 | 青 |
| 2 | **今日 > 終了日（未完了）** | `delayed` 遅延 | 赤 |
| 3 | 開始日・終了日が無い | `no_period` 期間未設定 | 灰 |
| 4 | 今日 < 開始日 | `not_started` 開始前 | 灰 |
| 5 | 上記以外 | `on_track` 対応中 | 緑 |

**「順調」ではなく「対応中」と呼ぶ**：終了日だけで判定しているので、進み具合が良いかどうかは分からない。
「まだ終了日を過ぎていない」以上のことは言えないため、言い切らない名前にする。

**割り切り**：終了日が来るまでは、実態として遅れかけていても「対応中」のままになる。
遅れの兆しは、進捗バーに重なる縦線（予定進捗、F-2-7）と §3.2 の進捗率を、人が見て判断する。

> 完全版では「実績 − 予定」の差にしきい値（−10pt で注意、−25pt で遅延）を当てていた。
> 簡易版はこれを持たないため、**「注意」（黄色）が無く、しきい値の設定も無い**。
> 判定が進捗率の入力状況に左右されない代わりに、早期の兆しは出せない。

### 3.4 補足ルール

- **親の状態は親自身の終了日で判定する**（子の状態の最悪値を伝播させない）。
  ただし一覧では「配下の遅延件数」を併記し、親が順調でも中に遅延があることがわかるようにする。
- 保留は進捗率をそのまま使い、状態の判定は通常どおり行う。一覧では保留チップを別途表示する。
- 開始日・終了日が未設定のタスクは状態の判定対象外とし、「期間未設定」と表示する。

## 5. Google Apps Script での実装方針

### 5.1 全体の形

```
[ブラウザ] 1ページの Web アプリ（HTML + JS）
    │  google.script.run
    │    ① 起動直後  getSummary()  … projects + summary_cache + users（軽い）
    │    ② 続けて裏で getItems()   … items 全件（重い。画面はもう出ている）
    │    ③ 保存のたび saveItem() など（変更した行だけ）
    ▼
[GAS] doGet / getSummary / getItems / saveItem / …
    │  SpreadsheetApp
    ▼
[スプレッドシート] 1シート = 1テーブル（9シート）
```

| 方針 | 理由 |
|---|---|
| **画面は1ページ**。モックは画面ごとに別ファイルだが、実装では1つの HTML の中で表示を切り替える | GAS の `HtmlService` はページ遷移のたびに `doGet` が走り、毎回2〜4秒かかる。遷移のたびに待たせない |
| **2段階で読み込む**。まず集計キャッシュ（F-5-6）で一覧を出し、その裏でタスク全件を読む | プロジェクト一覧は50行だけ読めば描ける。1,000行のタスクを待たずに最初の画面が出る |
| **判定・集計・検索はすべてブラウザ側の JS で行う** | サーバー実行は6分制限があり、同時実行も詰まる。読み込んだ後はサーバーへ行かない。横断検索（F-5-10）も裏で読んだタスクに対してその場で走るので待ち時間ゼロ |
| **書き込みは変更した行だけ**（`setValues` で1行）。`LockService.getScriptLock()` で囲む | 全体書き戻しは遅く、同時編集で上書き事故が起きる |
| **書き込みのついでに集計キャッシュを更新する**。そのタスクが属するプロジェクトの1行だけ | 読むたびに1,000行を数え直さずに済む |
| **衝突の検知**は `updated_at` の比較で行い、「他の人が先に更新しています。再読込してください」と出す | 10名規模ならこれで足りる。行ロックまでは作らない |
| 認証は `Session.getActiveUser().getEmail()` を `users` シートと照合 | GAS の標準機能で済む |

裏での読み込みが終わるまでは、横断検索・マイタスク・担当者一覧に「読み込み中」を出す。
プロジェクト一覧とプロジェクト概要は、集計キャッシュだけで先に描ける。

### 5.2 シートの決まり

- 1行目を列名のヘッダー行にし、コードは**列名で引く**（列の順番に依存しない）。
- 主キーは文字列の UUID（`Utilities.getUuid()`）。
- 日付は `yyyy-MM-dd` の文字列で持つ（タイムゾーンのずれを避けるため、日付型にしない）。
- JSON を入れる列（`custom_fields` など）は文字列として保存し、読み込み時に `JSON.parse`。

### 5.3 判定ロジックの置き場所

§3 の計算は**引数だけで答えが決まる純粋な関数**として1ファイルにまとめる。
ブラウザ側で動かすほか、集計キャッシュの更新（§5.1）とお知らせの生成（§5.4）でサーバー側からも呼ぶ。
同じ判定が2か所で食い違わないよう、コードは1つにする。

### 5.4 お知らせの作り方（F-5-9）

| 種類 | いつ作るか |
|---|---|
| 担当になった／外れた | 担当者を変えて保存したとき、その場で作る |
| 期限の前日と当日 | **毎朝の時間主導トリガー**（`ScriptApp.newTrigger` で 7:00 頃）でタスクを走査して作る |
| 遅延になった | 同じ朝のトリガー。前日は遅延でなかったタスクが遅延になったときだけ作る |

- 朝のトリガーは1,000行の走査と書き込みで、6分の実行制限には十分収まる。
- 既読フラグは `notifications` シートの行を更新する。
- 90日より古いお知らせは、同じトリガーで削除する（行が際限なく増えないように）。

### 5.5 人は共通マスタから読む（F-5-13）

別システム（稟議システム）と同じ共通マスタを、**読むだけ**で使う。作法もそちらに合わせる。

| 決まり | 理由 |
|---|---|
| スプレッドシートIDはコードに書かず、スクリプトプロパティ `COMMON_MASTER_SS_ID` に置く | 本番とテストで別のブックを指すため |
| **書き込む関数を置かない**（`Common.gs` は読む関数だけ） | オーナーとデプロイ者が同じアカウントになりうるので、権限では止められない。境界を担保するのはコードだけ |
| `getDisplayValues()` を使う | `getValues()` だと所属コード `23-1` が日付になり、先頭ゼロが消える。**コードは文字列として扱う** |
| 列は名前で引く | 列は予告なく末尾へ増える |
| 参照してよいシートを許可制にする | `社員一覧` / `所属マスタ` / `役職マスタ` / `同期ログ` 以外は内部構造で予告なく変わる |
| 人は**社員コード**で指す。メールは使うそのときに引く | common 側でメールが変わっても担当の紐づけが切れない |
| 既定は**在籍者だけ** | 退職者も同じシートに残っている。担当の候補に出さない |

**読めないときも止めない**：最後に読めた内容をこのアプリのブックの隠しシート（`_common_控え`）に
控えとして持ち、共通マスタが開けないときはそれで動かす。控えは人が編集しない（機械が上書きするだけ）。
どこから読んだか（common ／ 控え ／ ローカル）を画面に出す。

共通マスタの同期は止まっていても読めてしまうので、`同期ログ` で今日走ったかを見て、
走っていなければ画面に知らせる。「鮮度」とは呼ばず「同期が今日走ったか」と書く。

### 5.6 各ページに直接アクセスできる（F-6-1）

画面は1ページだが、URLで画面を指定して開けるようにする。

| URL | 開く画面 |
|---|---|
| `?p=projects` | プロジェクト一覧（既定） |
| `?p=detail&id=<ID>` | プロジェクト詳細 |
| `?p=task&id=<ID>` | タスクの編集を開いた状態 |
| `?p=mine` / `people` / `search` / `new` / `notifications` | それぞれの画面 |

画面を切り替えるとURLも変わる（`google.script.history`。ページの再読み込みはしない）。

**安全のための決まり**

- **URLの値は信用しない。** 画面名は決め打ちの一覧（`ALLOWED_PAGES_`）に無ければ一覧に落とす。
  IDは形だけを見て通し、実在はブラウザ側で読み込んだデータで確かめる。
  無ければ「見つかりません」とだけ返す（当てずっぽうのIDが実在するかどうかを教えない）。
- **URLは権限を与えない。** リンクを知っていても、ウェブアプリの公開範囲の外の人は開けない。ここはGoogleが守る。
- **いまはプロジェクト単位の閲覧制限が無い**（admin / member の2段階のみ・§7.3）。
  つまり、直接リンクで開けるものは一覧からたどっても開ける。**見せる相手を絞る必要が出たら、
  URLではなくデータを返す側で絞る**こと（`getBootstrap` / `getItems` で返さない）。

## 6. 非機能要件

| 項目 | 目標 |
|---|---|
| 初回読み込み | プロジェクト一覧が出るまで**2秒以内**（集計キャッシュのみ）。タスク全件は起動データと**同時に**取りに行く（順番に待たない） |
| 画面の切替・横断検索 | 即座（サーバーへ行かないため） |
| 保存 | 2秒以内。保存の戻り値（保存後の行と、そのプロジェクトの集計1行）だけで画面を合わせ、全件の読み直し・起動データの取り直しはしない |
| サーバーの読み書き | 1回の呼び出しの中で、スプレッドシートは1度だけ開き、同じシートは1度だけ読む（書いたら手元の内容も合わせる）。ログイン中の人は10分覚える。共通マスタの控えは中身が変わったときだけ書く |
| 同時利用 | 5名程度の同時操作で破綻しないこと |
| データ保全 | スプレッドシートの版履歴に依存。日次でコピーをバックアップ |
| ブラウザ | Chrome / Edge の最新版 |
| 表示 | レスポンシブ（375px 〜 1920px）、ライト/ダークモード対応 |
